# Інтеграція з «Облік-Плюс» (бухгалтерія)

_Автор: Сергій (billing team), березень 2021. Оновлено після інциденту з лютневим імпортом._

Бухгалтерія веде облік у «Облік-Плюс». Щоночі ми кладемо їм файл, о 06:00
їхній сервер забирає його сам.

## Звідки файл

- Генерує: `bin/nightly-export.js` (cron 02:30 на старому сервері).
- Куди: `out/export/oblik-YYYY-MM-DD.csv` → шара бухгалтерії (монтується).
- Колонки: `config/export-columns.json`. Бухгалтерія може попросити переставити
  колонки — це правиться в JSON без деплою. **Типи колонок не міняти.**

## Формат, який вони приймають

| Що | Як |
|---|---|
| Кодування | UTF-8 |
| Роздільник | `;` |
| Кінець рядка | CRLF |
| Перший рядок | заголовки колонок |
| Дата | **`MM/DD/YYYY`** — сервер «Облік-Плюс» стоїть з американською локаллю |
| Суми | крапка як десятковий роздільник, без пробілів і без «грн»: `1234.50` |
| Текст | без `;` і переносів рядків |

## Чого ніхто не бачить

«Облік-Плюс» **не падає** на рядку з датою в іншому форматі. Він цей рядок
**пропускає**, а в журналі імпорту на їхньому боці пише попередження, яке ніхто
не читає. Ні помилки в нас, ні листа від них.

У лютому 2021 ми так «втратили» 40 рахунків: хтось поміняв форматування дати,
тести були зелені, а рахунки просто не потрапили в облік. Знайшли через три
тижні, коли не зійшовся звіт з ПДВ.

Тому: **будь-яка зміна того, як форматуються дати чи суми, — спершу подивитись,
що буде з цим файлом.**
