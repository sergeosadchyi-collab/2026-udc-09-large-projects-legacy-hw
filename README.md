# UDC Workshop 9 — великі проєкти та legacy-код з AI

- **Слайди:** <https://koldovsky.github.io/2026-udc-09-large-projects-legacy-slidev/>
- **Повні інструкції:** [`docs/walkthrough.md`](docs/walkthrough.md)

Домашнє завдання: зробити **дрібний тікет у великому старому коді** — і
дізнатися, що ще зачепить ця дрібна правка, **до** того, як дізнається хтось
інший.

## Швидкий старт

```bash
gh repo fork koldovsky/2026-udc-09-large-projects-legacy-hw --clone
cd 2026-udc-09-large-projects-legacy-hw
git checkout -b ws09/<github-username>

cd app && npm test
```

106 зелених тестів. `npm install` не потрібен — у застосунку **немає жодної
npm-залежності**. Потрібно: Node 22+ і GitHub account. **Жодних API-ключів.**

## Що вже є

| Шлях | Що це |
|---|---|
| `app/` | Бек-офіс білінгу вигаданої компанії, якому вісім років: 86 файлів, ~10 тис. рядків, 13 модулів, 25 HTTP-маршрутів, cron-скрипти. CommonJS і колбеки |
| `app/docs/` | Документація самої системи. **Частина її застаріла** |
| `materials/ticket-BILL-482.md` | Тікет: дата в рахунках у неправильному форматі |
| `docs/templates/` | Шаблони для всіх документів домашки |

Усі дані в `app/data/` — синтетичні.

## Що робите ви

- **Task A** — карта кодової бази від агента, і перевірка щонайменше 10 її тверджень по коду
- **Task B** — хто насправді залежить від зміни + характеризаційні тести **до** зміни
- **Task C** — сама зміна, яка нічого не ламає
- **Task D** — де агент помилявся (або контрольний прогін) + `app/AGENTS.md` для наступного агента
- **Task E** (бонус) — навігація трьома способами / мутаційне тестування / план виведення старого модуля

## Правила гри

Робіть лише те, що просить тікет. Не переписуйте legacy на ESM чи async/await,
не додавайте залежностей, не чіпайте `app/data/*.json`. Маленький диф — частина
оцінки.
